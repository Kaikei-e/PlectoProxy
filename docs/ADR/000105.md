# polyglot 実用スターター群を examples 帯に追加し、token-cost admission を契約 0.4.0 の最初の実例とする

## Status
accepted

## Date
2026-08-13

## Affected Components
- examples/filters — `filter-tokenlimit-js` / `filter-tokenlimit-moonbit` / `filter-tokenlimit-go` を追加（starter 帯・棚外）
- host tests — `tokenlimit_battery/` 共有アサーション（Tier A 13 / Tier B 14）を追加
- ci — `test-features` ジョブに 3 ゲストのビルドを折り込み（wall-time 増分はビルドのみ ~1–2 分）
- docs — `writing-a-filter.md` §7・`plecto/examples/README.md`・`reference-filters.md` の Not-on-shelf を更新

## Context

[[000068]] が F2 の残存 reference 目標として **AI/LLM token-cost レート制限**（`host-ratelimit` の
`(key, cost)` を使うもの）を名指ししていた一方、非 Rust ゲストの実例は 4 言語すべてが同一の
`filter-hello` conformance サブセットの移植で、**「実用例」が一つも存在しなかった**（[[000080]]
Decision 3 が fixture と明示する帯のみ）。さらに現行契約 `plecto:filter@0.4.0`（[[000104]]）を使う
出荷済み example も皆無で、「新しく書くなら現行契約」というドキュメントの主張に実例が伴っていなかった。

DX 推進の観点では、開発者が自分の言語で「動く実用コードを fork して始める」入口が欠けていることが
最大のギャップであり、ROADMAP M6 も fixture 1 個どまりを超える template 群を pending としていた。

題材選定は開発者調査で裏付けた。業界の本番形は estimate → admit → **reconcile**（実 usage 照合と
返金）の三段だが、`host-ratelimit` の WIT 表面は `try-acquire(key, cost)` のみで refund を持たない
（確定事実）。したがって本 starter は前半二段（estimate–admit）の実装であり、課金の正本にはなれない。
`chars ÷ 4` + `max_tokens` 予約 + 429 / `Retry-After` という形は公開仕様・慣行と整合する妥当な
第一近似である。また crypto 系題材（HMAC / JWT）は Tier B ツールチェーンの `crypto/hmac` が
wasi CI から除外されている等のランタイム未実証リスクがあり、初の polyglot 実用例には不適と判断した。

関係する Tenet / Fork: deny-by-default capability（バケット仕様は operator 所有、[[000026]]）、
フィルタはステートレス、fail-closed、判断は型で。

## Decision

1. **題材は token-cost admission**。リクエスト body の JSON から
   `cost = max(1, (ceil(utf8_bytes/chars-per-token) + max_tokens) × model 係数 / 100)` を整数算で
   見積り、`host-ratelimit.try-acquire(key, cost)` で消費する。`(key, cost)` API の最初の実例。
2. **starter 帯（examples）に置き、署名 shelf には載せない**。[[000080]] の shipped 定義を満たす
   意図がなく、載せると「課金の正本」と誤読される。[[000081]]（`filter-ratelimit-redis` の棚外維持）と
   同型の理由を `reference-filters.md` の Not-on-shelf に明文化した。
3. **3 言語（JS/TS・MoonBit・Go）で同一挙動**。仕様が沈黙するエッジ 6 点（`max_tokens` の非整数と
   1e8 クランプ、非 UTF-8 キーの 401、係数パース不能時のリクエスト trap、`chars-per-token` の
   init trap、空 `key-header` の init trap、128 バイト超モデル名の照合スキップ）を fail-closed 側に
   裁定し、共有アサーションバッテリー（golden vectors）で固定した。
4. **契約は 0.4.0、subset world**。export は `init` / `on-request` / `on-response` /
   `on-request-body` のみで、`on-response-body` を持たないことにより応答ストリームの zero-copy を
   保つ（[[000098]] の受理格子の実例）。import も `host-log` / `host-config` / `host-ratelimit` の
   3 interface に絞る。
5. **Tier 構成は現行 ADR に従う**。Tier A（JS・MoonBit）は zero-WASI（[[000055]]）、Go は自前
   compose world + 最小 WASI スライス（[[000063]]）。既存 `filter-hello-go`（契約 0.1.0）は
   ロード時アダプタの生きた互換性証拠として不可触のまま残す。
6. **estimate–admit のみを実装し、reconcile / refund は非目標**と README で契約的に明示する。
   デフォルト manifest は spoofing 回避のため auth チェーン（`filter-apikey` → tokenlimit、
   `key-header = "x-authenticated-user"`）を動く形で示す。

**検討した代替案と却下理由**:
- *reference shelf の多言語化* — 保守面積が言語数×フィルタ数で増え、「一名前一 artifact」原則の
  改定も要る。production 保証の誤読リスクが DX の利得を上回る。
- *言語ごとに異なる題材* — カバー範囲は広がるが挙動比較が不能になり、テストを言語別に三重設計する
  ことになる。polyglot conformance の「同一アサーション」思想（[[000055]]）にも反する。
- *0.3.0 での追加* — 既存 fixture のビルド配線を流用できるが、「新規は現行契約」という
  メッセージと矛盾する。0.4.0 の実例欠如という別の穴も埋まらない。
- *crypto 系題材（HMAC webhook / JWT）* — 実務需要は高いが、Tier B での `crypto/hmac` 未実証
  リスクと、pure 実装の暗号コードが本質を覆い隠す教材上の難点で見送り。

## Consequences

### Pros
- 非 Rust ゲストに初の実用 starter が生まれ、ROADMAP M6 の template ギャップを埋める。
- 契約 0.4.0（bare `%continue`・`path-with-query`・`list<u8>` ヘッダ）の最初の出荷実例。
- `(key, cost)` の重み付き admission、fail-closed init、pooled instance 安全の per-request
  scratch 規約、subset world による zero-copy 維持——設計 tenets の実演が一題材に収まる。
- 挙動は共有バッテリーが 3 言語横断で保証し続ける（Tier A 13 / Tier B 14、全 green で着地）。
- CI は既存 `test-features` への折り込みのみで、cargo invocation 数は増えない。

### Cons / Tradeoffs
- ポリシー本文の三重保守。緩和策として JS を canonical copy-target、Go を Tier B 実例、
  MoonBit を最小 Tier A と役割宣言し、挙動の正本は共有バッテリーに一本化した。
- 見積らないフィールド（tools・非 string content・system）は文書化された undercharge 境界。
  production fork は「数えるか拒否するか」を選ぶ必要がある。
- 係数パース不能時のリクエスト trap は、pooled 構成で circuit breaker（3 連続 trap で冷却）と
  相互作用し、壊れた係数を持つモデルが同一 route の他モデルへ断続 503 を波及させうる。
  fail-closed 方向だが運用ノートに値する。
- JS component は実行エンジン定数 ~12 MB を含み、artifact サイズが言語で桁違いになる。
- **再検討条件**: (1) `host-ratelimit` に refund / reconcile を足す契約変更を検討する時
  （estimate–admit–reconcile の第三段が可能になり、本 starter の非目標宣言を見直す）。
  (2) starter の shelf 昇格を検討する時（単一保守対象の選定・見積り明示・スキーマ conformance・
  auth チェーン E2E が条件）。(3) Tier B の前提が upstream Go の reactor 対応で変わる時。
