# wasmtime 48.0.0 にロックステップで追随し outbound WASI 面の破壊的変更を吸収する

## Status
accepted

## Date
2026-08-21

## Affected Components
- workspace manifests — `wasmtime` / `wasmtime-wasi` / `wasmtime-wasi-http` を 47.0.3 → 48.0.0（caret 継続）。`spike/streaming-async/host` の独立 workspace も同時に bump
- `crates/host/src/engine.rs` / `streaming.rs` — 48 監査結果のコメント追記のみ（Config 変更なし）
- `crates/host/src/outbound_tcp.rs` — `allow_tcp(true)` 明示、`SocketAddrUse` 新 variant 対応、`PlectoResolveStream` 導入
- `crates/host/src/outbound_http.rs` / `state.rs` — crate root へ移動した wasi-http hook 面への追随、connector 再実装
- `crates/host/benches/wasm_inst.rs` / `bench/methodology.md` — 測定除染と依存 bump 再ベースライン手順

## Context

wasmtime 48.0.0 が 2026-08-20 にリリースされた（MSRV 1.95.0 — 現行 toolchain 1.97.1 で無風）。
一次ソース（リリースノート・各 PR・release-48.0.0 ブランチのソース実体）を確認した監査結果:

- **新規 default-on proposal はゼロ**。GC / exception-handling は 47 から default-on のままで、
  engine は引き続き明示 off。fixed-length-lists（#12315）と implements / external-id リフレクション
  （#13874）は opt-in で出荷され、有効化しない（deny-by-default）。[[000096]] が bump 手順として
  定めた「default-on 監査」はこの一行で閉じる。
- **セキュリティ**: 同日公開の 2 advisory の affected range に 47.0.3 が含まれる。
  GHSA-vqjp-4c8c-hfgg（High 8.8、`wasi:filesystem` の末尾スラッシュ symlink による sandbox escape、
  cap-std 由来）と GHSA-x84v-gj2h-g759（Moderate、WASIp3 stream 経由の guest 制御サイズ host heap
  確保）。Plecto は preopen ゼロの inert filesystem 貸与（[[000063]]）かつ p3 面を一切有効化して
  いないため**どちらも到達不能**だが、「patch セキュリティ修正は常に取る」方針（CHANGELOG の
  versioning policy、[[000084]] の security 優先例外）の対象。
- **`wasmtime-wasi` 48 の破壊的変更**が feature-gated の outbound 面に直撃する:
  (a) TCP/UDP socket 生成が default deny 化（#13936）— 47 の `tcp: true` default に暗黙依存して
  いた `outbound-tcp` は明示 `allow_tcp(true)` がないと socket 生成の時点で全滅する。
  (b) `SocketAddrUse` の再定義（#13934、リリースノート未記載）— `TcpListen` / `TcpAccept` /
  `UdpSend` / `UdpReceive` が追加され、connect が内部で行う implicit bind も `TcpBind` として
  チェックを通るようになった。
  (c) p2 の `ResolveAddressStream` が private フィールドの newtype になり、ホスト側から構築不能に
  なった — [[000060]] の名前解決 vetting（allowlist・SSRF 分類・IP pin）は独自 Host 実装が前提。
  (d) `wasmtime-wasi-http` の hook 面（`WasiHttpView` / `WasiHttpHooks`）が crate root へ移動し
  `send_request` の形状が一新、47 が全 connector に無条件適用していた between-bytes-timeout の
  ラップが `default_send_request` の内側へ移った — connector を自前で持つ [[000036]] の経路では
  誰も適用しなくなる。
- **Cranelift が dead-store elimination を獲得**（#13806/#13947、default opt level で有効）。
  component fused adapter の `MAY_LEAVE` フラグ store を狙う最適化で、命令数ゲートの再ベース
  ラインが必須になる。
- **過去の bump パターン**: 「.0.x パッチを待つ」方針は文書にも履歴にも存在しない（47.0.1 は
  47.0.0 リリース翌日に採用、47.0.3 は upstream リリース当日に採用）。一方で API が動く major
  追随は専用ブランチで行う前例がある（[[000021]]）。

streaming increment（`stream<u8>` 本固定）のゲート（[[000021]] / [[000025]] の再検討条件）に
ついて: 48 には stream 系 correctness fix が 3 件入っており（#13891 ホスト producer/consumer が
EOF 初回 poll で drop されず guest await が永久 hang、#13914 future の write-closed 誤 trap、
#14018 コンポーネント間 stream の intra-instance 誤判定）、Stage 2 相当の配管そのものが直り
続けている。これは spike 再開には過去最良の環境である一方、**correctness fix がまだ流れ続けて
いる事実自体が「本固定はまだ早い」の根拠**であり、`wasm32-wasip3` の Tier 2 化も未達。

## Decision

**48.0.0 へ直行する（47.0.4 を挟まない）。専用ブランチで作業し、宣言は caret `"48.0.0"` を継続する。**

1. **経路 — 48.0.0 直行**。検討した代替案: (a) 47.0.4 のみ（却下: stream fix・DSE・#13871 等
   48 の修正を得られず、到達不能とはいえ published affected range 内に留まり続ける）、
   (b) 47.0.4 を main に即取りしてから 48 ブランチ（却下: 両 advisory とも到達不能が確認済みで
   緊急性がなく、レビューと CI を一本化する方を優先）。
2. **ピン方針 — caret 継続**。47 期の「最新 patch を追い、Cargo.lock が解決版をピンする」方針を
   維持（patch 即取りポリシーと整合）。代替案の `=48.0.0` 完全固定は、patch のたびに manifest
   変更を要し方針と摩擦するため却下。
3. **outbound-tcp**: policy がある場合のみ `allow_tcp(true)` を明示（policy なしは 48 の default
   がそのまま「socket 生成自体を deny」— 上流が Plecto と同じ deny-by-default に寄った）。
   `permits()` は `TcpConnect` のみ許可し、connect が意味する **wildcard implicit bind
   （unspecified IP + port 0）だけを carve-out** として通す。`TcpListen` / `TcpAccept` / UDP 系は
   全 deny。明示の wildcard bind が implicit と区別不能で通る軽微な広がりは受け入れる（listen が
   deny である限り wildcard-bound socket は何も受信できず inert）。
4. **ip-name-lookup**: テーブル格納型を自前の `PlectoResolveStream` に置き換え、生成 bindings とは
   `Resource::new_own(rep)` / `new_borrow(rep)` の rep-cast で橋渡しする。`subscribe` へは
   **borrowed handle** を渡す（owned を渡すと pollable が親の所有権を引き取り、pollable drop 時に
   stream エントリを道連れ削除して guest の stream drop が trap する — 実測で確認）。検討した
   代替案: (a) 上流実装への置換（却下: allowlist・SSRF 分類・IP pin の vetting が消える —
   [[000060]] の核）、(b) `wasi:sockets/ip-name-lookup` を自前 bindgen（却下: バージョン付き
   interface 登録の再実装リスクが rep-cast の局所性に見合わない）。
5. **outbound-http**: crate root の新 `send_request`（boxed future ペア）へ connector を再実装。
   [[000036]] の total-timeout seam は不変。between-bytes-timeout は**47 の実挙動を維持**する —
   47 でも guest の request-options 値は使われておらず、connector が `policy.total_timeout` を
   between-bytes 値として渡していた。それをそのまま body の per-frame bound として自前適用する。
   字義どおり guest の options 値を使う案は却下: 実運用のフィルタは request-options を設定して
   おらず、未設定時に上流 default の 600 秒へ**黙って緩む**。
6. **bench**: `wasm_inst` の fixture を返り値化して teardown を測定外へ出す（除染）。除染後の
   真の delta は **pooled −8.87% / untrusted fresh −6.16%（命令数、DSE による改善）**、fast path
   3 ベンチはビット同一。除染前の旧値は 9 割以上が teardown で、48 で Host/Engine teardown が
   約 3 倍化（cranelift / regalloc2 メタデータの解放が drop 時へ移動）したことで汚染が顕在化した。
   `pre_wt48` を pre-bump named baseline として保存し、依存 bump 再ベースライン手順を
   `bench/methodology.md` に明文化した。
7. **streaming increment のゲートは維持**（本固定せず）。48 の stream fix 群は spike 再開の
   好条件だが、ゲート条件（wasip3 Tier 2 + wit-bindgen async 成熟）は未達。

Tenet との関係: deny-by-default（監査で新規開放ゼロを確認、上流 default の deny 化とも整合）と
fail-closed（allow_tcp 欠落時の挙動は「全滅」= 安全側で、機能退行としてのみ修正）を具体化する。
[[000096]] の bump 手順（default-on 監査）を踏襲し、本 ADR で 48 分を記録する。

## Consequences

### Pros
- published affected range（High 8.8 含む 2 advisory）から脱出。
- DSE により per-request 命令数が改善（pooled −8.87% / fresh −6.16%）。pooling allocator の
  per-thread sharding（#13840、設定不要）による lock 競合減も自動享受。
- 上流 `wasmtime-wasi` の socket default が Plecto と同じ deny-by-default になり、貸与の意図が
  コードに明示された（暗黙依存の解消）。
- `wasm_inst` ゲートの測定純度が上がり、以後の contract 表面コスト判定が per-request シグナル
  だけを見る。

### Cons / Tradeoffs
- **Host/Engine teardown の約 3 倍化は未追跡**。hot path 外だが、SIGHUP reload や pool recycle
  の頻度が高い運用では顕在化しうる。再検討条件: reload / recycle レイテンシに運用上の不満が
  出たら teardown を独立測定する。
- 明示の wildcard bind（`0.0.0.0:0`）が implicit bind と区別不能で許可される軽微な広がり
  （listen deny により inert）。
- guest の request-options between-bytes-timeout を尊重しない 47 からの現状を維持。再検討条件:
  streaming increment の本固定時に body タイムアウトの契約意味論ごと再設計する。
- `LinkerInstance` の再オープン許容（#13908）により、同名 instance への二重登録が 47 のエラー
  から 48 の黙認追記に変わった。capability 配線の重複ミスに気づきにくくなる方向 — 配線の回帰は
  conformance の import 列挙（[[000108]]）が下流で受け止める。
- **49 監視項目**（次回 bump 時の必須確認）:
  (a) #14045 — bulk operation（`memory.fill` 等）内の preemption point 撤去が 49 に入る。巨大
  copy が epoch deadline を突き破って走り切れるようになり、fail-closed の deadline 前提
  （[[000006]]）に効く。49 bump 時に `StoreLimits` 側の上限での補完を検討する。
  (b) stream 系 correctness fix の流量が 49/50 でも続くか — streaming increment の「枯れ」判定の
  実測指標。
  (c) sync-call オーバーヘッド（upstream #12311、component-model-async 有効時 ~2.3x）は未解消。
- wasmtime 48 同梱の wasm-tools は 0.254、Plecto の `wit-component` は 0.255 — 並立を許容
  （`deny.toml` の multiple-versions = warn 運用）。`include_component_type` 採用の検討（別 ADR
  予定）で整合を判断する。
