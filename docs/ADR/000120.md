# wasmtime 50.0.0 へロックステップ更新し、49.0.2〜50.0.0 のセキュリティ修正と wasm-tools 0.261 系列を取り込む

## Status
accepted

## Date
2026-10-21

## Affected Components
- `plecto/Cargo.toml` — `wasmtime` / `wasmtime-wasi` / `wasmtime-wasi-http` を 49.0.1 → 50.0.0、`wit-component` を 0.258 → 0.261。`spike/streaming-async/host` の独立 workspace も同時に bump
- `crates/host/src/engine.rs` / `streaming.rs` — 50 監査結果のコメント追記（Cranelift での新規 default-on proposal なし。GC / exception-handling / wide-arithmetic の明示 off は維持）
- `crates/host/src/contract_target.rs` — `wit_component::targets`（0.261）の第 4 引数 `canonical_names: false` への追随（`ComponentEncoder::default()` およびエンジンの `wasm_component_model_canonical_names` 既定 off と一致）
- `crates/host/Cargo.toml` — test 専用の `wat` を 1.261 へ
- `.github/workflows/ci.yml` / `release.yml` — wasm-tools CLI を 1.261.0（sha256 固定）へ
- `docs/ROADMAP.md` — ホスト追随版数の記述を wasmtime 50 へ更新

## Context

wasmtime 50.0.0 が 2026-10-20 にリリースされた（MSRV 1.96.0 → 1.97.0、#14466 — Plecto は `plecto/Cargo.toml` で
`rust-version = "1.97"` を宣言し、`plecto/rust-toolchain.toml` で 1.97.1 に固定済みのため無風）。
一次ソース（crates.io、[`bytecodealliance/wasmtime` `release-50.0.0/RELEASES.md`](https://raw.githubusercontent.com/bytecodealliance/wasmtime/release-50.0.0/RELEASES.md)、
[`v50.0.0/Cargo.toml`](https://raw.githubusercontent.com/bytecodealliance/wasmtime/v50.0.0/Cargo.toml)、
[`v50.0.0/crates/wasmtime/src/config.rs`](https://raw.githubusercontent.com/bytecodealliance/wasmtime/v50.0.0/crates/wasmtime/src/config.rs)、
GitHub Security Advisories）で確認した事実:

- **セキュリティ修正**: 49.0.1（2026-09-24）以降、49.0.2（2026-10-02）・49.0.3（2026-10-14）・
  49.0.4（2026-10-19）および 50.0.0（2026-10-20）で多数の advisory が修正された。現行の 49.0.1 は
  これらの影響範囲にあり、50.0.0 はすべてを包含する。Plecto の利用面（Component Model async・
  `wasi:http`・最小 WASI スライス・Cranelift）に関係する主な修正は以下のとおり:
  - GHSA-w4qr-p94g-mjhv（medium）— `wasi:http` で `between-bytes-timeout` に 0 を渡すと Tokio 側でホストが panic する DoS
  - GHSA-32h6-97mm-8q3c — component async-lifted callback の戻り値数未検証によるネイティブスタックバッファオーバーフロー
  - GHSA-gqmc-89g8-p25r — guest に stdio を貸していない場合のホスト側過剰メモリ確保
  - GHSA-54p9-vhhq-8f7q — fused adapter の文字列トランスコードで重複メモリ領域によりホストが panic しうる
  - GHSA-5qpp-g3j2-8frx / GHSA-w36r-2hch-9xp9 — `wasi:http` の `path-with-query` における authority-form URI 注入と長大 URL でのホストクラッシュ
  - GHSA-3r89-v5mq-j5xf / GHSA-m6w2-jwq2-cv2c — component `call_async` キャンセル時や async-lifted 関数呼び出し時のホスト panic
  - GHSA-r8xh-cgf7-392j（#14824）— `wasi-http` で重複した `Content-Length` ヘッダを拒否
  - GHSA-9prg-84vf-g5fc（#14822）/ GHSA-jxcf-8qw5-5c33（#14823）— `wasi-http` p3 における response body の `Content-Length` 強制と trailer の禁止ヘッダ検査
  - GHSA-mghf-wjfp-p5xm（#14826）— Cranelift aarch64 における巨大な分岐数を持つ `br_table` の修正
  - GHSA-9pvw-hwfg-92h5（#14827）— Component Model の future / stream 型検査の一元化
- **新規 default-on proposal 監査（[[000096]] の bump 手順）**: 50.0.0 の `Config::features()` を 49.0.1 と
  比較した結果、Cranelift（`Strategy::Auto` / `Strategy::Cranelift`）で新たにデフォルト有効化された
  WebAssembly proposal は**ない**（ベースは `WasmFeatures::WASM3 | WasmFeatures::WIDE_ARITHMETIC` で不変）。
  50.0.0 で新設された `Config::wasm_compact_imports`（#14335）・`Config::wasm_component_model_canonical_names`（#14344）・
  `Config::wasm_component_model_accessors`（#14497）はいずれもデフォルト `false`（opt-in）である。
  よって、既存の `wasm_gc(false)` / `wasm_exceptions(false)` / `wasm_wide_arithmetic(false)` の 3 点で
  49 系と同一の deny-by-default 命令面が維持される。
- **同梱 wasm-tools 系列**: 50.0.0 は wasm-tools 0.261 系列（`wit-component` / `wit-parser` /
  `wasmparser` 0.261.0）を同梱する。[[000114]] の静的契約ゲート（`wasmtime::component::wit_parser` と
  `wit_component::targets` の型一致）により、`wit-component` を 0.261 へ、CI / release の wasm-tools CLI を
  1.261.0 へ揃える必要がある。
- **API・挙動変更**:
  - `wit_component::targets`（0.261.0）に `canonical_names: bool` 引数が追加された（#14344 関連）。
    Plecto の `ComponentEncoder::default()` およびエンジンの `wasm_component_model_canonical_names`（既定 `false`）と
    一致させるため、`contract_target.rs` では `false` を渡す。
  - `Store::epoch_deadline_callback` / `call_hook` の引数が `StoreHookState` に変更（#14386）、および
    `Accessor::spawn` が `AsyncFnOnce` を取る形に変更（#14376）されたが、Plecto は `set_epoch_deadline` の
    デフォルト trap 動作のみを使い `Accessor::spawn` を呼ばないため無影響。
  - `new_borrow` で作った `Resource<T>` の `ResourceAny` 変換がコール外で panic しなくなり（#14384）、
    `Store::set_epoch_deadline` の極端な delta でのオーバーフローが修正された（#14513）。
  - pooling allocator がページアウト済みページのリセットや広域スキャンを正しく行うよう改善され（#14357）、
    コンパイル間のキャッシュ済みコンパイラコンテキスト破棄により定常メモリ使用量が削減された（#14314）。

関係する Tenet は「deny-by-default capability」（[[000006]]）と「データプレーンで panic 禁止」である。
とくに後者は、`wasi:http` や Component Model async 経路で guest 入力からホスト panic を引き起こしうる
複数の advisory（GHSA-w4qr-p94g-mjhv、GHSA-54p9-vhhq-8f7q、GHSA-3r89-v5mq-j5xf 等）を塞ぐことに直結する。

## Decision

1. **`wasmtime` / `wasmtime-wasi` / `wasmtime-wasi-http` を揃えて 50.0.0 へ bump する**。
   workspace manifest での一括管理と `spike/streaming-async/host` の同時更新を維持する。
2. **両エンジン Config（`engine.rs` / `streaming.rs`）の明示 off 設定（GC / exception-handling / wide-arithmetic）を維持し、50 監査コメントを追記する**。
3. **`wit-component` を 0.261 へ、`wat` を 1.261 へ、CI / release の wasm-tools CLI を 1.261.0 へ上げる**（[[000114]] の系列一致）。

検討した代替案:

- **49.0.4 へのパッチ bump に留める** — 49 系の最新セキュリティパッチでも 49.0.2〜49.0.4 の advisory は
  取り込めるが、50.0.0 リリース時点で 50 系と同時公開された修正（#14822〜#14827）や pooling allocator /
  component-model-async の改善を取り込み、M3 Stage 1 以来の「最新 major をロックステップで追う」方針
  （[[000021]] / [[000096]] / [[000113]] / [[000117]]）を一貫させるほうが保守コストが低い。ホスト側の
  コード変更が不要（監査コメントのみ）であるため、50.0.0 へ直接進める。

具体化する Tenet: 「deny-by-default capability」と「データプレーンで panic 禁止」（[[000096]] で定めた bump 手順の 4 回目の適用）。

## Consequences

### Pros
- 49.0.2〜50.0.0 で修正された計 20 件超の advisory（`wasi:http` / Component Model async のホスト panic DoS、
  URI 注入、重複 `Content-Length`、メモリ枯渇、スタックオーバーフロー等）の影響範囲から外れる。
- untrusted フィルタへの wasm 命令露出面が 49 系と完全に同一のまま 50 系へ乗れる（ホスト実装の破壊的変更ゼロ）。
- pooling allocator のページリセット改善（#14357）とコンパイラコンテキスト破棄（#14314）の恩恵をそのまま受ける。

### Cons / Tradeoffs
- wasm-tools 系列（0.258 → 0.261）のジャンプに伴い、CI / release の wasm-tools CLI tarball と sha256 を更新する運用が続く。
- 再検討条件: 50.0.x パッチリリースで追加の security advisory が出た場合、または guest に新たな wasm proposal を貸す需要が生じた場合。
