# Rust 1.100 の wasm32-wasip3 Tier 2 昇格を受け streaming-body fixture を wasm32-wasip3 ビルドへ移し、既定化は wit-bindgen async の成熟まで保留する

## Status
accepted（決定確定・実装・検証済み）

## Date
2026-11-14

## Affected Components
- host build.rs fixture build（`plecto/crates/host/build.rs`）— `build_wasi_component(..., target, ...)` に `wasm32-wasip3` を渡し、`streaming-body` 有効時の `filter-streaming` を `filter_streaming-wasip3.wasm` として出力する（outbound 系 fixture は `wasm32-wasip2` を維持）
- filter-streaming guest（`plecto/examples/filters/filter-streaming/`）— `wasm32-wasip3` ビルドへ移行。`streaming-body` feature 自体は引き続き既定 off とし、`wit-bindgen` 0.62 系に留める
- CI jobs clippy / test-features / guest-lint（`.github/workflows/ci.yml`）— `clippy (all features)`・`test-features`・`guest-lint` の 3 ジョブに `wasm32-wasip3` ターゲットを追加し、`guest-lint` で `filter-streaming` を `--target wasm32-wasip3` で clippy 検査する
- rust toolchain pin 1.100.0（`plecto/rust-toolchain.toml`・`.github/workflows/*.yml`・`Dockerfile`・`plecto/Cargo.toml`）— Rust ツールチェーン固定を `1.100.0` へ引き上げる（`wasmtime` 50.0.1 および `wit-bindgen` 0.62 は変更しない）
- docs（`CLAUDE.md`・`docs/design-principles*.md`・`docs/ROADMAP.md`・`plecto/crates/host/CONTEXT.md`・`plecto/examples/README.md`・`CHANGELOG.md`）— `wasm32-wasip3` Tier 2 到達の事実と、既定化が `wit-bindgen` async の成熟および `wasmtime` 51 系列待ちである旨を同期する

## Context

[[000003]]（Fork 1: 非同期ファースト契約・`stream<u8>` ボディ）は、当面 `wasm32-wasip2` でビルドしつつ P3 WIT をターゲットとし、ゲストツールチェーンが `wasm32-wasip3` を正式サポートした時点で追従する移行戦略を定めた。また [[000021]] の再検討条件 (a) は、Stage 2 ゲートを「`wasm32-wasip3` Tier 2 化 ＋ `wit-bindgen` async 成熟」の二条件で定義し、[[000025]] が自前 `body` resource を先行させつつ真の `stream<u8>`（`plecto:filter-streaming`）を `streaming-body` feature 裏へ隔離した。

**確定事実（一次情報で確認）**:
- **Rust 1.100.0（2026-11-12）** が `wasm32-wasip3` を **Tier 2 without host tools** へ昇格させた（[Rust 1.100.0 release blog](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/)、[rustc platform-support: wasm32-wasip3](https://doc.rust-lang.org/rustc/platform-support/wasm32-wasip3.html)）。stable `1.100.0` では `rust-std` が配布されるが、直前の `1.99.1` では未配布だった（[channel-rust-stable.toml](https://static.rust-lang.org/dist/channel-rust-stable.toml)）。
- 同ターゲットは `wasm-component-ld` により協調的スレッディング（cooperative threading）でリンクされ、shadow stack pointer を Component Model のタスクコンテキストスロットに保持する。`std::thread::spawn` は既定で未サポートである（[wasm32-wasip3 platform-support](https://doc.rust-lang.org/rustc/platform-support/wasm32-wasip3.html)）。
- **WASI 0.3.0** は 2026-06-11 に批准され、最新リリースは **0.3.2**（2026-10-13）である（[WebAssembly/WASI releases](https://github.com/WebAssembly/WASI/releases)）。
- **wasmtime** の最新安定版は **50.0.1** であり、**51.0.0** は 2026-11-05 時点で **rc.1**（プレリリース）に留まる。
- **wit-bindgen 0.63.0**（2026-10-14）には wasip3 async 修正（`Task` handle、`wasip3_task_vtable`、TLS 保持）が入ったが、同系列のクレートは `wit-parser` / `wit-component` `^0.262` を要求する。一方 [[000114]] は `wit-component` を `wasmtime` 同梱の wasm-tools 系列へロックステップ固定しており、`wasmtime` 50.0.x は `0.261`、`51.0.0-rc.1` は `0.263` を同梱する。

**状況の評価（確定事実と projected の区別）**:
- 上記の確定事実より、[[000003]] が置いた追従トリガ（「ゲストツールチェーンの `wasm32-wasip3` 正式サポート」）は **発火した**。
- 一方、[[000021]] 再検討条件 (a) の Stage 2 ゲート（「`wasm32-wasip3` Tier 2 化 ＋ `wit-bindgen` async 成熟」）は、**前半のみ充足し、後半は未充足**である。`wit-bindgen` 0.63 の取り込みと async 成熟度評価は、**projected（未確定・計画）**として `wasmtime` 51.0.0 GA の着地後に実施する位置づけになる。

## Decision

1. **`streaming-body` fixture（`plecto/examples/filters/filter-streaming`）を `wasm32-wasip3` ビルドへ移行する。**
   - `plecto/crates/host/build.rs` の `build_wasi_component(..., target, ...)` により、`CARGO_FEATURE_TEST_SUPPORT` と `CARGO_FEATURE_STREAMING_BODY` の両方が有効な場合のみ `filter-streaming` を `wasm32-wasip3` でビルドし、成果物 `filter_streaming-wasip3.wasm` を出力する（既定ビルドでは触れない）。
   - **実測根拠（確定事実）**: `wasip2` ビルドでは `wasi:io/{poll,error,streams}`・`wasi:clocks/{monotonic-clock,wall-clock}`・`wasi:cli/*`（`@0.2.12`）を import していたのに対し、`wasip3` ビルドの import は `wasi:cli/{environment,exit,types,stdin,stdout,stderr,terminal-*}@0.3.0` および `wasi:clocks/{types,monotonic-clock,system-clock}@0.3.0` のみに縮小する。`wasi:io`・filesystem・sockets の import は一切含まれない。
   - このため `plecto/crates/host/src/streaming.rs` の既存 deny-by-default な streaming `Linker`（`plecto/crates/host/src/state.rs` の `add_wasi_base_p3` が既に p3 の clocks / random / cli を貸与済み）に対し、エンジン設定変更・リンカ変更・新規 capability 付与なしでそのまま instantiate できる。必要な wasm feature は `streaming.rs` が既に有効化している Component Model async のみである。

2. **outbound 系 fixture 群は `wasm32-wasip2` を維持する。**
   - `filter-extauthz`・`filter-jwt`・`filter-tcp-gate`・`filter-ratelimit-redis`・`plecto/crates/host/fixtures/filter-tcp-retain` の契約は [[000036]] / [[000060]] が定める p2 の `wasi:http` / `wasi:sockets` 貸与に立脚している。これらを `wasip3` ビルドへ移すと、`wasip3` `std` によって該当 capability 経路に第 2 の WASI import 集合が追加されてしまうため、`wasm32-wasip2` に据え置く。

3. **`streaming-body` は既定 off を維持し、`wasmtime` 50.0.1 と `wit-bindgen` 0.62 を据え置く。**
   - [[000021]] の後半条件（`wit-bindgen` async の成熟）が未充足であるため、`streaming-body` の feature gate は既定 off のまま維持する。
   - [[000114]] に従い、`wasmtime` はリリース済み安定版 `50.0.1`、`wit-bindgen` は `0.62` 系列に留める。

4. **Rust ツールチェーンを `1.100.0` へ固定し、CI の必要最小限の 3 ジョブに `wasm32-wasip3` を追加する。**
   - ツールチェーン pin を `1.100.0` へ更新する（`plecto/rust-toolchain.toml` および各ワークフロー等）。`plecto/rust-toolchain.toml` の既定 `targets` には `wasm32-wasip3` を加えず（通常ビルドは同ターゲットを要しない）、CI（`.github/workflows/ci.yml`）の `clippy`（`clippy (all features)`）・`test-features`・`guest-lint` の 3 ジョブのみに `wasm32-wasip3` を追加する。`guest-lint` では `filter-streaming` を `--target wasm32-wasip3` で `cargo clippy` する。

**検討した代替案と却下理由**:

- **`wasmtime` 51 系まで `filter-streaming` も `wasm32-wasip2` のまま据え置く** — 却下。
  [[000003]] の追従トリガ（ゲストツールチェーンの公式サポート）は既に発火している。`wasip3` 移行は現時点でテスト全通過を確認済みであり、かつ `wasi:io` 等の import 集合を縮小できるため、先送りして `wasip2` との二重状態を長引かせる理由がない。
- **`streaming-body` を今すぐ既定（default）へ昇格する** — 却下。
  [[000021]] 再検討条件 (a) の後半（`wit-bindgen` async の成熟）が未充足であり、`wasmtime` 51 も rc 段階にある。さらに `docs/design-principles.md`（および `.ja.md`）第5章は feature gate の既定化には独立した昇格 ADR を要求している。
- **outbound 系 fixture 群も `wasm32-wasip3` へ同時に移行する** — 却下。
  判断 2 のとおり、[[000036]] / [[000060]] の p2 `wasi:http` / `wasi:sockets` 契約へ `wasip3` `std` 由来の第 2 の WASI import 集合を持ち込むことになり、capability 境界を不必要に広げる。
- **`wit-bindgen` 0.63 を取り込むために `wasmtime` `51.0.0-rc.1` を採用する** — 却下。
  プレリリース版への追随は [[000114]] が前提とする「リリース済み `wasmtime` 系列とのロックステップ」に反する。

**具体化する Fork / Tenet**:
本決定は [[000003]]（Fork 1: 非同期ファースト契約・`stream<u8>` ボディ）の方向を `wasm32-wasip3` ビルドによって前進させつつ、[[000006]] および `CLAUDE.md` コア原則・`docs/design-principles.ja.md` P4（deny-by-default: 不要な `wasi:io` を import 面から排除し、未成熟な `streaming-body` を既定ビルドから隔離し続ける）、P10（証拠に従う）、第5章（トリガ → 個別 ADR → 実装）を具体化する。

## Consequences

### Pros
- `filter-streaming` の WASI import 面から `wasi:io`（`@0.2.12`）が消え、`wasi:cli/*@0.3.0` と `wasi:clocks/*@0.3.0` のみに縮小した。既存の `add_wasi_base_p3` による deny-by-default な streaming `Linker` 上で、エンジン・リンカ無改変かつ新規 capability 追加なしで instantiate できる。
- [[000003]] が定めた `wasm32-wasip3` 移行経路を、既定ビルドや outbound 経路に影響を与えずに先行実証できた。
- **検証結果（Rust 1.100.0 上で実施済み）**:
  - `cargo clippy --all-targets --all-features --locked -- -D warnings`: clean
  - `cargo test --all --locked`: 761 passed / 0 failed
  - `cargo test -p plecto-host -p plecto-control --features plecto-host/streaming-body,plecto-host/outbound-http,plecto-host/outbound-tcp,plecto-control/outbound-http,plecto-control/outbound-tcp`: 540 passed / 0 failed（`tests/streaming.rs` の 3/3 を含む）
  - `cargo fmt --check`: clean
  - 注記: polyglot Tier A/B スイートはローカルでは未実行（各ゲストのツールチェーンは本変更の影響を受けず、CI が実行する）。

### Cons / Tradeoffs
- CI の 3 ジョブ（`clippy`・`test-features`・`guest-lint`）で `rust-std`（`wasm32-wasip3`）のダウンロードが増える。
- streaming `Linker` は `wasip2` でビルドされたゲストを引き続き動かすため、p2 proxy スライス（`wasmtime_wasi::p2::add_to_linker_proxy_interfaces_async` / `add_cli_runtime`）を併存リンクしたまま維持する。
- `filter-streaming` fixture が、`wasip3` `std` の前提とする `wasmtime` 側の Component Model async task-context 処理（shadow stack pointer の保持等）に依存する。
- `wasm32-wasip3` の既定制約により、ゲスト内では `std::thread::spawn` が利用できない。
- **再検討条件**:
  - **`wasmtime` 51.0.0 GA のリリース**: [[000114]] の手順に従い `wit-component` `0.263` / `wit-bindgen` `0.63` へロックステップ追随したうえで、`wit-bindgen` async の成熟度を評価し、`streaming-body` 既定化の可否を**独立した昇格 ADR** で判断する。
  - **将来の `wasip3` `std` による import 拡張**: 将来の Rust 更新で `wasip3` `std` が filesystem や sockets を import するようになった場合、現行の deny-by-default な streaming `Linker` は設計どおりリンク失敗するため、それを検知トリガとして見直す。
  - **p2 proxy スライスの整理**: サポート対象の streaming ゲストで p2 ビルドのものが無くなったら、streaming `Linker` から p2 proxy スライスを撤去する。
